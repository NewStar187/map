# 직접 하실 일

코드와 문서로 끝나는 부분은 이 폴더에 들어 있다. 아래는 계정, 키, 실제 도구 사용처럼 사람이 해야 하는 일이다. 위에서부터 순서대로 하면 된다.

## 1. Supabase 프로젝트 만들기

1. https://supabase.com 에 가입하고 새 프로젝트를 만든다. 지역은 서울(Northeast Asia)을 고른다.
2. 왼쪽 메뉴의 SQL Editor를 열고 `supabase/schema.sql` 내용을 붙여 넣어 실행한다.
3. 같은 방법으로 `supabase/seed.sql`, `supabase/storage.sql`을 차례로 실행한다.
4. Project Settings → API에서 Project URL과 anon public 키를 복사한다.
5. 이 폴더에서 `config.example.json`을 `config.json`으로 복사하고 두 값을 넣는다. `assistUrl`은 3번을 마친 뒤 넣는다.

anon 키는 화면 코드에 들어가도 되는 공개용 키다. service_role 키는 모든 규칙을 건너뛰는 비밀 키이므로 어디에도 붙여 넣지 않는다.

## 2. 운영자 계정 만들기

1. Authentication → Users에서 본인 이메일로 사용자를 추가한다.
2. Table Editor → profiles에서 그 사용자의 `is_admin`을 true로 바꾼다.
3. `node build.mjs`를 실행한 뒤 `dist/admin.html`을 열어 로그인되는지 확인한다.

## 3. AI 도우미 켜기

1. https://console.anthropic.com 에서 API 키를 만든다. 사용량 한도를 낮게 걸어 둔다.
2. Supabase 대시보드 → Edge Functions → Secrets에 `ANTHROPIC_API_KEY`라는 이름으로 키를 넣는다. 키는 채팅이나 코드, `config.json`에 적지 않는다.
3. Supabase CLI를 설치하고 이 폴더에서 `supabase functions deploy assistant`를 실행한다.
4. `config.json`의 `assistUrl`에 `https://<프로젝트 주소>.supabase.co/functions/v1/assistant`를 넣고 다시 빌드한다.

`assistUrl`이 비어 있으면 도우미는 지금처럼 정해진 규칙으로만 동작한다.

## 4. 가격과 약관 확정하기

`docs/가격-약관-확인목록.md`의 체크 항목을 원문에서 확인한다. 값이 다르면 `data/tools.json`을 고치고 `node tools-seed.mjs`를 실행한다. 이미 데이터베이스에 넣은 뒤라면 운영 화면이나 Table Editor에서 고친다.

## 5. 예시 결과물 뽑기

`docs/기준-프롬프트.md`의 프롬프트를 각 도구에 그대로 넣어 결과를 받고, 저장소의 `examples` 버킷에 올린다. 도구마다 계정과 요금이 필요하다.

## 6. 시작용 평가 넣기

팀원이 실제로 써 본 결과물을 서비스에서 올리고, 운영 화면의 ‘결과물 검토’에서 공개한다. 공개된 결과물만 별점에 들어간다.

## 7. 배포하기

1. 이 폴더를 GitHub 저장소에 올린다. `config.json`은 `.gitignore`에 들어 있어 올라가지 않는다.
2. Vercel 또는 Netlify에서 저장소를 연결한다. 빌드 명령과 내보낼 폴더는 `vercel.json`, `netlify.toml`에 적혀 있다.
3. 배포 서비스에는 `config.json`이 없으므로, 배포 전에 빌드해 `dist` 폴더를 올리거나 배포 설정에서 `config.json`을 만들어 주는 단계를 추가한다.
